<description>Decrypt inbound control messages in ResourceAllocator</description>
<read_first>
- multi-tunnel-namespace/src/daemon/resource_allocator.py (message dispatch loop)
</read_first>
<action>
1. In `ResourceAllocator`, import `from libvpnmanager.security.totp_crypto import decrypt_message`.
2. In the method that receives a request from an adapter (likely `_handle_client` or `_dispatch`), after reading the JSON (a dict `request`), check for encryption:
   - Retrieve the corresponding adapter record from the registry using the connection's authenticated identity (PID lookup already done).
   - If `adapter.totp_secret` is not None and the request dict contains the keys `'totp'` and `'encrypted'`:
     - Extract `totp_code = request['totp']` (string).
     - Decode ciphertext: `ciphertext = base64.b64decode(request['encrypted'])`.
     - Decrypt: `plaintext_bytes = decrypt_message(ciphertext, totp_code)`.
     - Parse the plaintext bytes as JSON: `inner = json.loads(plaintext_bytes.decode('utf-8'))`.
     - Replace `request` with `inner` for further processing.
   - If decryption fails (exception from decrypt_message or JSON parse), log error and send an error response: `{"msg_type":"error","error":"DECRYPTION_FAILED","code":"DECRYPTION_FAILED"}`. Close writer or continue as appropriate.
3. Log at debug level when decryption occurs: `f"Decrypted control msg type {msg_type} with totp {totp_code}"`.
4. Ensure `import base64` and `import json` are present.
</action>
<acceptance_criteria>
- resource_allocator.py imports `decrypt_message`.
- Code branch checks `adapter.totp_secret` and presence of `'encrypted'` in request.
- Performs base64 decode, decryption, JSON parse, and replaces request.
- On failure, returns structured error with `DECRYPTION_FAILED`.
- Debug log mentions decryption.
</acceptance_criteria>
</task>

<task id="3" type="auto">
<description>Encrypt outbound control responses when TOTP enabled</description>
<read_first>
- multi-tunnel-namespace/src/daemon/resource_allocator.py (where response is constructed and sent)
</read_first>
<action>
1. Still in `ResourceAllocator`, after constructing the `response` dictionary (before sending), check if the adapter has `totp_secret` and the original request included a `totp` field (the TOTP code used by the adapter).
   - If `adapter.totp_secret` is not None and `'totp'` in original request:
     - Serialize the response to JSON bytes: `body = json.dumps(response).encode('utf-8')`.
     - Encrypt: `ciphertext = encrypt_message(body, request['totp'])`.
     - Build a new response: `encrypted_response = {"msg_type": "encrypted_response", "totp": request['totp'], "encrypted": base64.b64encode(ciphertext).decode('ascii')}`. Alternatively, preserve the original `msg_type` in the envelope. Simpler: use `{"msg_type": response.get("msg_type"), "totp": request['totp'], "encrypted": ...}`. But downstream will expect an encrypted envelope; we need a consistent protocol. Using a top-level `"encrypted"` field indicates the payload is encrypted. The spec in research suggests the response includes `"totp"` and `"encrypted"`. So:
       ```python
       envelope = {
           "msg_type": response["msg_type"],
           "totp": request["totp"],
           "encrypted": base64.b64encode(ciphertext).decode('ascii')
       }
       response = envelope
       ```
     - Send this modified `response`.
   - If no TOTP, send the plain response.
2. Ensure the adapter client code (later) knows to look for `encrypted` and extract the inner message.
3. Add necessary imports: `from libvpnmanager.security.totp_crypto import encrypt_message` and `import base64`.
4. The response should be a dict that will be JSON-encoded by the existing send logic.
</action>
<acceptance_criteria>
- resource_allocator.py imports `encrypt_message`.
- After building response, there is logic that checks `adapter.totp_secret` and `'totp'` in request.
- The response is replaced with an envelope containing `msg_type`, `totp`, and `encrypted` (base64 string).
- Without TOTP, the response is unchanged.
</acceptance_criteria>
</task>
