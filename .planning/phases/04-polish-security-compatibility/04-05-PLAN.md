<description>Adapt dummy adapter to use TOTP encryption on control channel</description>
<read_first>
- multi-tunnel-namespace/src/adapters/dummy_adapter/cli.py (control message sending and receiving)
- multi-tunnel-namespace/src/libvpnmanager/security/totp_crypto.py
</read_first>
<action>
1. In the adapter's startup (after reading stdin payload), store `self.totp_secret = payload.get('totp_secret')`. It may be `None` if TOTP disabled.
2. For sending control messages (Register, AllocateTunnel, ReleaseTunnel):
   - If `self.totp_secret` is not None:
     - Generate or obtain current TOTP code. For now, use a stub: `totp_code = "123456"` (later real TOTP from stored secret).
     - Serialize the plaintext message dict to JSON bytes.
     - Encrypt: `ciphertext = totp_crypto.encrypt_message(plaintext_bytes, totp_code)`.
     - Build envelope: `{"totp": totp_code, "encrypted": base64.b64encode(ciphertext).decode('ascii')}`.
     - Send the envelope instead of the plaintext dict.
   - If `self.totp_secret` is None: send plaintext dict as before.
3. For receiving responses from MTM:
   - Parse incoming JSON.
   - If the message has an `encrypted` field:
     - Decrypt: `plaintext_bytes = totp_crypto.decrypt_message(base64.b64decode(encrypted), totp_code)` where `totp_code` is the `totp` field from the envelope. Note: Need to use the same totp_code that was sent in the request. Store it per outgoing request? Simpler: since TOTP is time-synced, we can recompute expected TOTP from `self.totp_secret` and verify against the received `totp` field before decrypting. But the message should have been encrypted using that TOTP. We'll trust that the same totp is used; in production, verify. For stub, just use provided totp.
     - Use the decrypted dict as the actual response.
   - If no `encrypted`, use as plaintext.
4. Add necessary imports: `import base64`, `from libvpnmanager.security import totp_crypto`.
</action>
<acceptance_criteria>
- Adapter CLI stores `self.totp_secret` from startup payload.
- Sending control messages checks `if self.totp_secret is not None` and wraps in `{"totp": "...", "encrypted": "..."}` envelope using `totp_crypto.encrypt_message`.
- Receiving response checks for `encrypted` field and decrypts with `totp_crypto.decrypt_message` before processing.
- Both dummy and proton adapters have identical logic (apply same changes to both).
- If `totp_secret` is None, plaintext mode used (backward compatible).
</acceptance_criteria>
